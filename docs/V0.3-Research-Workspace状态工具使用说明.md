# V0.3 Research Workspace 状态工具使用说明

本说明用于在现有 MiniClaw 聊天客户端验收首个科研工具 research_workspace_status。当前不新增独立科研页面。

## 一、启动服务

在 PowerShell 中执行：

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\Agent\miniclaw-test\start.ps1"

打开 http://127.0.0.1:3310，并使用已经配置真实模型的管理员账号登录。

## 二、创建科研工作区

在聊天页点击“新建工作区”，填写：

| 配置项 | 值 |
|---|---|
| 名称 | BDGI Research |
| 执行模式 | 宿主机 |
| 工作目录 | E:\Agent\miniclaw-test\miniclaw-data |

工作目录必须精确指向 miniclaw-data，因为工具只在工作区根目录存在 research-workspace.json 时注册。

## 三、发送验收消息

在 BDGI Research 工作区发送：

> 请调用 research_workspace_status，只根据工具结果告诉我当前科研材料的 workspaceId、snapshotId、论文、预测批次、文件完整性和待处理问题。

不要在 Main Workspace 或其他普通工作区执行该测试；普通工作区不会注册科研工具。

## 四、预期结果

客户端回复应包含：

- status 为 ready。
- workspaceId 为 bdgi-research。
- snapshotId 为 SNAP-20260919-92afd6116c4d。
- manifest 为 1105/1105 文件存在。
- 论文包含 PAPER-BDGI。
- Prediction Run 包含 RUN-BDGI-SD-SAVED 和 RUN-BDGI-SC-SAVED。
- issues 为空。

本地完整材料中还应显示 10 个控制文件完成哈希检查且没有不一致。

## 五、常见结果说明

| 现象 | 原因与处理 |
|---|---|
| 创建工作区提示路径不允许 | 检查 config/mount-allowlist.json 是否包含 E:/Agent/miniclaw-test/miniclaw-data，然后重新启动 |
| 模型不知道 research_workspace_status | 确认当前工作区目录正确；重新启动服务并新建会话，避免继续使用旧的暖 Runner |
| status 为 degraded 且缺少约 279 个文件 | 当前目录来自 GitHub 克隆，TIFF 样本未上传；将本地 samples/evaluations 材料补齐后重试 |
| status 为 error 且提示 root 无效 | research-workspace.json 的 root 必须为相对值点目录 |
| status 为 degraded 且提示哈希变化 | 材料或元数据已经修改，需要人工确认后更新 manifest，不能直接忽略 |
