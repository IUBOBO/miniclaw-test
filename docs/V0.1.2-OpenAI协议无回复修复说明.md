# V0.1.2 OpenAI-compatible 消息无回复修复说明

日期：2026-09-18。适用项目：`E:/Agent/miniclaw-test`。

## 问题结论

OpenAI-compatible 协议传递本身已经生效。Runner 会话记录明确显示请求 API 为 `openai-completions`，上游返回 HTTP 400：DeepSeek V4.1 不接受 `medium`，并要求其推理档位参数放入 `chat_template_kwargs`。

网页看不到错误，是因为后端原本把 Agent 错误放入静默重试路径；失败的 Pi turn 还可能继续等待输入。两个行为叠加后表现为“消息发出但没有回复”。

另有两个独立现象：协议和 Base URL 不匹配时上游返回 404；切回 Anthropic 协议后，该第三方接口返回的流缺少正常停止原因。这些都属于 Provider 配置或兼容格式问题，不是消息没有进入后端。

顶部“未配置消息渠道”提示只影响飞书、Telegram 等外部渠道，不影响 Web 直接对话。

## 真实复测步骤

1. 在 Provider 设置中选择 `OpenAI Compatible`。
2. 使用服务商给出的 OpenAI Chat Completions Base URL，通常以 `/v1` 结尾；不要继续使用 Anthropic 的 `/anthropic` 地址。
3. 模型名保持服务商真实提供的精确值。
4. 在 Agent 推理档位中优先选择 `low`；V0.1.2 也会把该模型的 `medium` 映射为 `low`。
5. 保存后新建一次对话，发送“请只回复：API连接成功”。
6. 成功后再让 Agent 读取 Workspace 内一个测试文件，保存脱敏日志作为 P0 模型接入验收证据。

如果请求仍失败，聊天页现在应显示协议、地址或参数问题，不会继续表现为无提示的无限等待。排查时读取最新的 `logs/service-*.out.log` 和 `data/groups/main/logs/host-*.log`，不要把 API Key 写入文档或提交到 Git。
