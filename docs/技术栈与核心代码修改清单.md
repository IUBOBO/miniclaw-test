# MiniClaw 技术栈与核心代码修改清单

核对日期：2026-09-18。当前本地功能版本：V0.1.1。正式项目：`E:/Agent/miniclaw-test`。

本文是源码导航；功能完成情况仍以《项目进度与修改记录.md》为准。现有 Agent、工具、记忆等基座不代表科研扩展已经完成。本文仅新增文档，不提升功能版本。

## 1. 先理解项目怎么运行

```text
浏览器页面 web/src
  → HTTP API / WebSocket
后端 src/web.ts → src/routes/* → 业务服务与数据库
  → src/index.ts / src/group-queue.ts 编排任务
  → src/container-runner.ts 启动 Host 或 Container Runner
Agent Runner 的 pi-index.ts → runtime/pi/* → 模型与工具
  → 工具结果、流式事件、IPC 请求返回后端
  → 网页显示结果；后端保存业务记录
```

后端负责账号、权限、数据库及任务编排；Runner 负责调用模型和执行工具。需要保存业务数据的工具应走后端接口或 IPC，不要让 Runner 直接打开业务数据库。Host 模式在本机执行，没有容器隔离；“科研工具只读”是后续新增工具的约束，不能理解成整个基座已经只读。

## 2. 使用的技术栈

以下版本是本次读取项目声明的版本系列或指定版本，不是所有依赖的安装版本清单；实际解析版本看相应 pnpm-lock.yaml。

| 层次 | 技术 | 在项目中的作用 | 后续是否需要学习或修改 |
|---|---|---|---|
| 编程语言 | TypeScript、JavaScript ESM | 后端、前端、Runner 的主要语言 | 必须，优先掌握类型、异步调用和模块划分 |
| 运行环境 | Node.js；本地启动要求 22+，此前验证为 24.19.0 | 运行服务与工具子进程 | 了解版本兼容；不要随意切换运行环境 |
| 包管理与构建 | pnpm、TypeScript tsc；三个独立 package.json | 安装依赖、编译三部分 | 新增依赖时更新对应 pnpm 锁 |
| 后端 Web | Hono 4、@hono/node-server、ws | HTTP 路由、认证接口、实时事件 | 新增科研 API、推送研究进度时使用 |
| 数据库 | SQLite、better-sqlite3；当前声明 ^13.0.3 | 本地业务数据持久化 | 扩展研究任务与证据结构时修改 |
| 全文检索 | SQLite FTS5 | 工作区记忆文本检索 | 可复用；不是向量数据库或向量 RAG |
| Agent 基座 | @earendil-works/pi-coding-agent 0.84.2、pi-ai 0.84.2 | Agent 会话、模型适配、工具执行 | 复用 API，优先扩展适配层而非重写 SDK |
| 工具描述与校验 | Zod 4、TypeBox；MCP 工具定义与 Pi 适配 | 校验参数、描述工具、转换工具结果 | 四类科研工具的主要接入机制 |
| 前端 | React 19、React Router 7、Zustand 5 | 页面、路由、状态管理 | 做科研工作台与任务详情页时修改 |
| 前端样式 | Tailwind CSS 4、Radix UI | 布局与基础交互组件 | 优先复用现有组件 |
| 前端构建 | Vite 6（web 项目声明） | 开发预览与生产静态文件 | 一般不必修改配置 |
| 报告展示 | react-markdown、KaTeX、Mermaid、Recharts | Markdown、公式、图示、统计图 | 可复用展示研究报告与指标曲线 |
| 认证与日志 | bcryptjs、Cookie 会话、Pino | 密码校验、登录状态、结构化日志 | 复用；日志不要包含密钥或密码 |
| 测试 | Vitest；前端有 Playwright 配置 | 单元/集成回归及浏览器测试 | 功能测试与科研任务效果评测分开 |
| 可选部署 | Docker、Electron 39 | 容器 Runner、桌面端 | 当前先做本地 Web，不是首版科研闭环必需项 |
| 可选科研解析 | 尚未选定 PDF 解析与专业日志处理方案 | 论文提取、配置归一化、指标解析 | 待新增；Python/PyTorch 不是本服务已接入的科研执行栈 |

注意：根 package.json 的 engines 仍声明 >=20，与本地启动脚本 22+ 不一致，按本地启动要求执行，后续统一声明。better-sqlite3 使用 ^ 范围，具体版本由 pnpm 锁约束，不能把 package.json 称为精确锁定。

## 5. 对照科研目标：你接下来会改哪些代码

下面“建议新增”均为拟议路径，本次没有创建这些功能或文件。

| 目标 | 先阅读的现有入口 | 建议新增或扩展 | 最低验收 |
|---|---|---|---|
| 跑通真实模型 | 设置页面、runtime-config.ts、pi-provider.ts | 先在网页配置 Provider/Agent，不先改源码 | 一次真实对话与一次授权工作区文件读取 |
| 资料与证据模型 | db.ts、memory-store.ts | 建议新增 src/research/，划分证据、实验关联、来源校验；根据现有能力决定是否加表 | 文件、页/行号、哈希、代码版本、配置与日志可追溯 |
| 论文与笔记检索 | mcp-tools.ts、pi-tools.ts | 建议新增 Runner 的 research-tools/；先支持提取后的文本与 Markdown，再加入 PDF 解析 | 找到准确段落；无来源时说明缺口 |
| 代码定位 | 工具定义与 Host 工作目录处理 | research-tools/ 中增加有界仓库搜索 | 返回文件、符号、行号与 commit；拒绝越界路径 |
| 配置比较 | 工具定义、yaml 依赖 | 解析实际配置格式并输出结构差异；保留原始来源 | 模型、训练参数、数据划分、种子差异正确 |
| 日志解析 | 工具定义、已有日志格式样例 | 提取实际指标及运行状态，不只匹配漂亮数字 | 指标对应正确实验与计算口径，截断/缺字段有说明 |
| 研究任务上下文 | Agent Profile、prompt-plan.ts | 配置科研工作流；只加载当前问题相关证据 | 区分事实、推断、冲突和未知；不能仅改 Prompt 就宣称实现工具链 |
| 执行轨迹 | group-queue.ts、container-runner.ts、stream-event.ts | 科研任务 ID、步骤、耗时、错误、取消与重跑关联 | 成功/失败状态与实际工具结果一致 |
| 跨会话恢复 | memory-service.ts、workspace-memory-* | 研究问题、证据引用、待办和来源失效检查 | 新会话恢复状态；不宣称恢复训练进程或执行现场 |
| 科研工作台 | App.tsx、pages/、components/、stores/ | 建议新增任务列表、证据视图、实验对照与报告导出 | 页面可完成并查看一次研究任务 |
| Agent Eval | tests/、既有工具与任务记录 | 建议新增 tests/research/；独立保存人工答案、脱敏轨迹及评测结果 | 正常、缺资料、冲突、错误配置、日志不匹配、超时、接续均覆盖 |

优先顺序：模型真实调用 → 固定一套论文/代码/配置/日志材料 → 统一证据格式 → 四类工具逐项验证 → 完整任务流程 → 记忆与任务评测 → 工作台。首版先分析已有训练日志，不加自动长训练或 GPU 调度。

## 6. 哪些只需配置，哪些才需要开发

| 需求 | 优先做法 |
|---|---|
| 更换模型、API 地址或密钥 | 使用网页 Provider 配置；先确认协议兼容，密钥不写进源码 |
| 修改科研助手角色与回答规则 | 修改 Agent Profile 的 IDENTITY/SOUL/AGENTS/TOOLS；不是全局替换基座提示词 |
| 更换研究仓库和材料目录 | 配置工作区/研究目录，再验证访问边界；不把个人路径硬编码进通用工具 |
| 增加新的配置/日志文件格式 | 新增解析器、参数校验与真实样例测试 |
| 保存新的研究实体或增加证据状态 | 后端业务模型、数据库迁移、接口与前端一起评估 |
| 改页面名称、布局和展示 | 修改 web/src；无需改 Runner |
| 更改模型协议或工具执行行为 | 阅读 Runner 适配层并补回归；不只改网页标签 |

## 7. 每次修改后的检查单

- [ ] 改的是正式目录下的源码，不是 dist、node_modules 或旧副本。
- [ ] 明确此次复用了什么基座能力，个人新增了什么。
- [ ] 修改工具时检查路径边界、参数、输出上限、来源与错误返回。
- [ ] 修改数据库时保留迁移与备份，不删 data 解决错误。
- [ ] 运行对应功能测试；用真实材料核验结论。接口通过不代表科研效果通过。
- [ ] 使用原 start.ps1 命令重新构建/启动，查看页面、健康检查及最新日志。
- [ ] 完成验收后更新进度表、证据位置和 LOCAL_VERSION；未完成写清剩余项。
- [ ] git status 和暂存差异检查后提交；不上传密钥、数据库、原始研究数据或运行日志。

当前验证边界：认证隔离回归曾通过；全量测试仍有失败项，详见进度文档。此导航只核对代码结构，不表示再次验收所有运行能力，也不证明已经接入某个真实大模型。
