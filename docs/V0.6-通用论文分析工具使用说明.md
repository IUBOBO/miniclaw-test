# V0.6 通用论文分析工具使用说明

## 目标

`research_paper_analyze` 面向“只有论文 PDF、尚未准备源码、配置、日志或结构化结果”的场景。用户可以指定已登记的 `paper_id`，也可以直接指定科研工作区内的相对 PDF 路径。

工具只读取文件，不修改论文、Manifest 或元数据。未登记论文以 `provisional` 状态分析，表示结论只绑定当前文件，不代表已经纳入科研快照。

## 输入

| 参数 | 说明 |
|---|---|
| `paper_id` | 已登记论文 ID，与 `paper_path` 二选一 |
| `paper_path` | 科研工作区内的相对 PDF 路径 |
| `max_sections` | 最多返回 1–12 个章节证据，默认 8 |
| `include_internal_evidence` | 明确审计时返回快照与 SHA-256，默认 false |

不传论文参数时，工具使用工作区 `default_paper_id`。绝对路径、父目录跳转、工作区外符号链接和超过 100 MB 的 PDF 会被拒绝。

## 输出

- 论文身份、相对路径、页数和登记状态。
- 摘要、引言、相关工作、方法、实验、结果、局限和结论的章节证据。
- 当前属于 `paper_only` 还是已经关联其他科研材料。
- 当前能够完成的论文总结、方法解释、论文内部实验分析、源码核验和运行核验能力。
- 缺少源码、结构化结果、配置、日志、数据和权重分别造成的影响。
- 结论边界：论文陈述不等于独立复现，未结构化的复杂表格不用于拼接精确数值。

普通用户输出不包含 workspaceId、snapshotId 或 SHA-256。扫描版或文字层不足的 PDF 返回 `OCR_REQUIRED`，不根据文件名生成内容。

## 只有论文时的回答方式

Agent 可以说明研究问题、作者提出的方法、论文内部实验和结论，并引用相应页码。回答使用“论文提出”“作者报告”等措辞，同时说明当前无法核验源码实现、训练执行和实验复现。

## 客户端验收

当前真实测试文件：`PDFpaper/UNet.pdf`。该文件没有论文元数据、代码、配置和日志关联。

在科研工作区的新对话中发送：

> 请调用 research_paper_analyze 分析 PDFpaper/UNet.pdf。用自然语言说明这篇论文的研究问题、方法、实验和结论，并告诉我目前缺少哪些材料、哪些结论无法进一步核验。不要展示工具状态、JSON、快照 ID 或哈希。

预期：

- 识别为 8 页、`provisional`、`paper_only`。
- 识别摘要和引言（第 1 页）、Network Architecture（第 4 页）、Experiments（第 6 页）和 Conclusion（第 7 页）。
- 可以总结论文、解释论文方法和分析论文报告的实验。
- 明确无法核验源码、配置、日志、数据、权重和独立复现状态。
- 最终回答使用自然语言和页码来源，不展示内部证据字段。

## 当前限制

- 章节识别基于可解释的标题规则，不是完整的论文版面模型。
- 不做 OCR；扫描版 PDF 只报告缺口。
- 未登记论文不会自动写入元数据或 Manifest。
- 未经结构化和人工核对的复杂表格不用于精确指标回答。
- 本阶段不执行源码、训练或评测。

自动测试和真实 PDF 直接调用通过后状态为“实现完成，客户端待验收”；客户端真实 Tool Calling 通过后再更新正式功能版本。
