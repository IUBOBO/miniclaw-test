# V0.5 源码定位工具使用说明

本阶段新增只读 `research_code_lookup`。工具只检索当前科研快照 `snapshot-manifest.jsonl` 中登记为 `source_code`，且位于对应模型 `code` 目录下的文本源码。

## 一、工具输入

| 参数 | 必填 | 限制 | 说明 |
|---|---|---|---|
| `query` | 是 | 1–200 字符 | 类名、函数名、变量名、模块缩写或代码片段 |
| `model` | 否 | 最长 100 字符 | 限定模型，例如 `BDGI-Net`；不填时检索所有登记模型 |
| `max_results` | 否 | 1–20，默认 10 | 限制返回的源码证据数量 |

## 二、返回内容与证据边界

每条匹配包含模型、定义或引用类型、最近源码符号、匹配行、上下文行号、有限长度源码摘录、工作区相对路径、快照 ID 和 manifest SHA-256。

工具每次读取前校验文件大小和 SHA-256，只接受 manifest 登记的源码；拒绝绝对路径、父目录跳转和符号链接越界。输出不包含宿主机绝对路径、远程路径、SSH 地址或密钥。

`no_matches` 表示当前登记源码没有命中，不能据此生成替代实现。文本命中只能证明源码位置和内容，不能单独证明该代码在某次实验中实际执行。

## 五、当前限制

- 当前是有界文本和符号定位，不构建 Python AST、调用图或类型推断。
- 最近符号根据源码定义行推断；复杂嵌套、动态绑定和反射代码仍需人工核对。
- 同一模型存在消融与历史副本时，正式 `model.py` 优先，但结果仍会明确返回各自路径和哈希。
- 本阶段不运行源码、不加载模型权重，也不证明训练或推理链路成功。
